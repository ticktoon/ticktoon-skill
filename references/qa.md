# 交付前检查与 12 格联系表

> `params` 配方（news-broadcast / bar-race / footage）使用固定模板，不跑 `tt qa`；build 后直接 `tt preview`。`tt qa` 对 params 工程会自动跳过；仍会做一次编译校验，参数/资源不合法时按 build 报错。

## 命令

```bash
node "$SKILL_DIR/platform/cli.mjs" qa --dir <dir>             # 轻校验：must 必须 0，同时产出 12 格联系表
node "$SKILL_DIR/platform/cli.mjs" det --twice --dir <dir>    # 编译指纹，两次必须一致
```

- `det` 比对的是规范化 `composition.json` 的 SHA-256，不是像素或 MP4 字节；带 `--tts` 时第一次会接 TTS、第二次强制不接，只有不带 `--tts` 才是严格同输入链。CI 内部两次都不接 TTS。
- `qa` 一次 build + 一次浏览器会话采样约 24–30 帧，只判两类硬问题：`RENDER_PAGE_ERROR` 与 `QA_INK_EMPTY`。安全框、碰撞、文字互压、字幕带、对比度、停留、时间维都**不自动判定**，直接看联系表。**只对 `code` 配方运行；`params` 配方使用固定模板，自动跳过。**
- 拿不准成片什么样：看 `review/qa-sheet.png` 的 12 格联系表（`tt qa` 自动生成），不要另跑抽帧命令。`code` 配方在 `must=0` 且联系表无明显问题后直接进入 `tt preview`，交用户人工检查；不要再用 `stills` 重复确认构图、稳定帧或入场过程。**禁止 FFmpeg 抽帧，禁止为了核对画面先导出 MP4 再截图；只有用户指定时刻或需要布局凭据时才用 `tt stills`。**

需要指定时刻的静帧时直接运行：

```bash
node "$SKILL_DIR/platform/cli.mjs" stills 5.6 --dir <dir>
# 输出 t5.60s 的完整 PNG 静帧和该时刻布局凭据，不需要 FFmpeg。
```

## 12 格联系表怎么读（不打分）

`tt qa` 把全片按时间顺序排成 4×3 的联系表，每格下方有时间码。先整体扫一遍，再放大看有问题的那一格；不要逐格打分。

按这 5 个问题看：

1. **开场**：第一格（约 6% 处）是否已经给出本题的锚点（标题、主形状或一个问题），而不是空纸或半笔？
2. **收尾**：末格（约 94% 处）是否收住？不该还留着半句话、半幅图或一支笔尖。
3. **可读性**：每格的主体是否一眼能认出；文字是否能在正常观看距离读清。哪一格需要眯眼，就回 storyboard 减字或放大层级。
4. **推进**：相邻格之间有没有变化（主体增加、视角变化、停顿）。连续三格几乎一样，就要问这一场是否没有信息增量。
5. **稳定**：字幕/注记是否总落在同一块区域。某格突然跳到别处或被画框截断，先查字幕样式和这一场的 `TT.text` / `TT.captionKit` 参数。

联系表只是视觉证据，不是评分卡，也不能替代完整预览。`code` 配方发现问题回到 storyboard 改，改完重跑 `tt qa` 看新图；`params` 配方直接改参数并 preview。
