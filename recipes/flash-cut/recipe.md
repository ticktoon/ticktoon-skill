# flash-cut · 快闪卡点

三句以上，每句一个结论，用硬切和大字连打；或者品牌口号、产品卖点、活动预告这种需要“大字占满画面”的短片。时长通常 6–30 秒。

选中本 recipe 后，内容怎么写、画面怎么画都以这一份文档为准。下面的物理规律与题材无关；每场写什么短句、用什么手法，由 `scene.code` 当场决定，本文件不给题材、不给句子模板。

## 先内容，后形式

- 先写一句**全片视觉命题**：观众要看见什么关系、冲突或变化，而不是先挑一个 ref-shot 套文案。没有视觉命题，不准开始排场。
- 先统一一套视觉系统：1 个主色 + 1 个强调色、1–2 种字体、1–2 类主角、1 个运动母题。至少 70% 的画面要让观众认出是同一部作品，不是每拍换一种审美。
- 全片必须有一个**持续变形的视觉母题**：同一个物体、符号、数字、方向或构图规则随内容变化。它负责把场次连起来，不能只靠 BGM 和硬切制造整体感。
- 每场从本句重新设计构图：字怎么变形、图怎么进入、视线往哪走、留白在哪里。不要为了“有变化”而随机更换卡片、相机、字体、配色和动画。
- `ref-shots/` 是**人工审阅过的高质量镜头库**。内容、气质和节奏命中时可以整体复用，包括版式、配色、参数和运动轨迹；部分命中时保留其视觉骨架，替换内容并按叙事调整。
- 可按需阅读多个镜头，不限制阅读数量。真正禁止的是：内容不匹配仍硬套、用示例顺序代替叙事顺序，或把有限镜头库当作全部可能的构图。
- 没有合适模板时必须主动发散：沿用同一套视觉标准，创造新的主角、构图和变形关系，而不是机械复刻来填满时长。
- 复用 ref-shot 时，区分内容替换与结构改写：文案、素材和颜色可以替换；构成该镜头识别性的视觉关系与运动方式默认保留。需要改变这些关系时，按新镜头设计并重新验证，不再视为原镜头的直接复用。

## 一句话原则

**每一场只做一件事：让一个大字/大数字/大图占住画面，然后切走。** 不是“排版一段文字”，是“把一句话砸到屏幕上”。

- 一场一个主角；主角可以是字、图像填字、数字、拼贴墙、波形或产品图。
- 配角只做三件事：色块、图案场、微标签（`01 / 06`、`129 BPM`、`EVERY = 1 FOOTNOTE = 1/5`）。
- 不铺陈、不解释、不写长句；短句直接给结论。
- 不是每场都要文字；图像、数据、波形也可以单独成场。

## 画面

- 逻辑画幅 1920×1080，`safeMargin = RULES.safeMargin`（本 recipe `0.025`）；字可以出血到 2.5%，但不要再把主字缩回字幕尺寸。
- 每场开头自己铺满底色：`ctx.fillStyle = '#...'; ctx.fillRect(0, 0, W, H);`。场景没有 `bg` 字段，漏铺就是画布黑底。
- 底色只用黑 `#0A0A0A`、纯白 `#FFFFFF`、橙 `#FF4D00`、深蓝 `#12305C` 这一组，或品牌明确给出的 hex；不要用纸白、米白、奶油色。不是整片白底，也不是默认黑底，按节奏换；纯白只用于“呼吸场”或数字刺点。
- 色块和卡片靠圆角、留白分界，不要画蓝色 UI 描边。
- 主标题（字、数字、图像填字）至少到画面高度的 1/5（1080p 约 216px）；满幅字可以到 0.8–1.6 倍画面宽。
- 同一场只允许三档：主字 > 微标签 > 注释。相邻两档不能接近；`RULES.scale` 的 `title 2 / label 0.72 / note 0.5` 只是起点，实际字号按画幅算。
- 全片同类型主标题共用一套字号适配规则（最大/最小字号与可用宽度）。相邻场主字可视高度不应无故相差超过 20%；文案过长优先缩句，不要让同一级标题突然小一圈。呼吸场、刺点场可以有意突破，但必须有节奏原因；黑白底切换时也要检查视觉字重。
- 字不加描边、不加投影、不加黑白边；粗细只来自字体。需要更粗字口时换更高字重的 manifest 字体，不用描边模拟。
- 微标签只做配角：编号、BPM、单位、脚注式短词；不要用微标签承担主句。

## 节奏

BGM 固定 `assets/bgm/fast-cut.mp3`（`audio.mood = cut`）：129.2 BPM，一拍 `0.4644s`，`beatOffset = 0.372s`。引擎不会自动把切点吸到拍上，**每场 `duration` 必须显式写成拍长的整数倍或半拍**：

| beats | duration |
|---|---|
| 0.5 | 0.2322 |
| 1 | 0.4644 |
| 1.5 | 0.6966 |
| 2 | 0.9288 |
| 3 | 1.3932 |
| 4 | 1.8576 |

- 单场最长 2.4s；超过就不是快切。
- 0.5 拍只做刺点：单字、数字、色块、闪白。
- 2–4 拍做完整画面：图像填字、拼贴墙、波形、数据卡。
- 一场里至少有一次动作变化：中点换色、换位、微标签跳数，或后半拍换构图，不要一个静止画面从头停到尾。
- 跨镜承接：上一场色块铺满 → 下一场同色底 + 残留圆/缩小的暗块；或上一场大字冲出画面 → 下一场同字落在新位置。一秒内的底色切换要成对，不要用叠化假装跨场。

## 镜头写法

以下写法都用原生 Canvas 在 `scene.code` 当场实现，不依赖快闪专用 kit。文字用 `TT.text`（按 `fontKey` 选字体）或 `TT.font(FONTS, size, fontKey)` 配合原生 `measureText` 排版；进度用 `TT.clamp01`，运动曲线用 `TT.ease.*`，确定性扰动用 `api.rng()`。需要遮罩、切片或重复装饰字时，用 `api.canvas()` 建离屏画布并通过 Canvas 合成模式与 `drawImage` 一次贴回，禁止像素回读。

`ref-shots/` 里每个文件是一场独立的高质量镜头参考，文件头格式见 `SKILL.md`。命中时可以整体复用其版式、配色、参数和运动轨迹，但不提供本片的叙事顺序；没有合适镜头时必须主动发散，仍用同一套 Canvas 与基础工具创造新构图。

- 不要为了展示手法而轮换：主导表现方式控制在 1–2 类，同一种构图不要连续重复。变化必须来自信息关系或母题推进，而不是“下一场该换另一个 ref-shot 了”。

1. **逐字弹入**：用 `Array.from` 拆字，`measureText` 累加逐字位置；每字延迟 0.05–0.08s，以 `TT.clamp01` 算独立进度、用 `TT.ease` 做回弹，再逐字 `TT.text`，字号占满宽度。
2. **图像填字**：用 `api.canvas()` 离屏绘制字形 mask，`api.video/api.img` 取素材后以 `source-in` / `destination-in` 合成，再把结果一次 `drawImage` 回主画布；字是窗口，不是字上贴图。
3. **棋盘 / 半调 / 斜条场**：用原生 `fillRect` / `arc` / 路径循环生成确定性图案，必要时 `clip()` 限定在大字或背景区域。
4. **数据卡 + 大数字**：用圆角矩形卡片、一排竖向 `fillRect` 和 `TT.text` 组合；柱高由 `TT.clamp01` 与 `TT.ease` 驱动，最后一根橙色，不要画成两条横向进度条。大数字放在卡外或卡内留白处。
5. **波形刺点**：黑底上用等距原生矩形组成白条，高度由索引与 `api.t` 的确定性函数计算，中点换橙。
6. **三段式版面 + 双向文字**：三条横带分别 `save/clip/restore`，文字重复绘制并用取模位移无缝循环；相邻带方向相反，逐带设置方向与速度。
7. **双层文字视差**：两行 `TT.text` 分别按 `api.t * dx`、`api.t * dy` 偏移，远近感靠矢量速度差而不是模糊。
8. **四格卡片 / 拼贴墙**：原生计算左高图、右上两小卡、右下宽字卡的矩形，使用圆角路径、`clip()` 和 cover 裁切贴图；圆角、无描边，不等格拼贴按内容单独算版式。
9. **双向格子墙**：按格子索引交替设置左右或上下入场方向，每格用独立的 `TT.clamp01((api.t - offset) / dur)` 进度；图片、文字、色块可以混排。
10. **卡片墙焦点巡览**：每帧由当前时间插值相机中心与缩放，`ctx.translate/scale` 后重画卡片墙，镜头贴三张卡做三角移动，末尾拉远全景；正文用小号 `TT.text` 放镜头外。
11. **圆 / 格子 / 条形揭图**：用原生圆形、格子或条形路径 `clip()`，再以 cover/contain 规则 `drawImage`，让素材本身当主角。
12. **格子焦点 → 原图铺屏**：先画格子墙，再用九参数 `drawImage` 将焦点格的源裁切矩形与目标矩形插值到完整原图，同镜放大铺屏，适合收尾。
13. **故障切片**：用 `api.canvas()` 离屏字版配合 `drawImage` 分段裁切，最后切 1–2 帧；按 `api.t` 在 1–2 个窗口爆发条带错位，窗口外保持干净字面，单字跳色，只切字不切背景。
14. **双向图片跑马灯**：上下两排图片/文字卡反向无缝循环，中间留主图；文字卡只用 2–4 字短词，图片用 cover 填满格子。
15. **双引号品质画面**：中央图片带只占中段并轻微推近，上下文字反向小位移，四角用大圆角双引号水印收束。
16. **代码编辑与实时预览**：代码按时间逐字出现，右侧用同一组公式回采样绘制运动，不执行场景外代码，不保留帧间历史。
17. **作品墙镜头巡览**：固定网格承载 4–6 张作品卡，镜头按关键帧推近单卡再拉远整墙；背景网格不随相机移动。

## 素材

- 有品牌图/产品图/实拍就优先用；没有就纯字 + 图案 + 色块，不要硬找无关图。
- 实拍/视频素材场不超过全片 1/3；快闪的主体仍然是字。
- 图像填字（离屏 Canvas mask）是重手法，不是默认手法：全片不超过 1/4 场，且不要连续两场都用。字就是窗口，默认无描边、无阴影、最多一层图片；不要给 mask 叠偏移层，也不要默认棋盘填充；图像填字场保持纯色底，不要上下再压棋盘条。窗口里的图默认静止，要横移/推近就按 `api.t` 计算 cover 裁切中心或缩放，所有位移都由当前帧推导。
- 图像填字的底色不要拍脑袋写黑或白：先取帧，在预览或静帧中判断图内明暗，从浅色 / 深色候选中选对比更强的一侧，微标签颜色跟着底色反选。底色和图内亮度接近时，字口边缘会糊成一片；不要在运行时为选色做 Canvas 像素回读。
- 没有图就用原生循环绘制棋盘、半调、斜条、色块，但它们是背景 / 图案场，不要塞进主字里冒充图片。
- 4:1 长图/横幅用 `contain`，不要 `cover` 把字裁掉。
- 视频资源声明 `{ type: 'video', name, src }`，代码里 `api.video(name)`；图片用 `api.img(name)`。

## 收尾

- 最后一场信息最少、字号最大；用故障、色块或单字收束，不再引入新元素。
- 最后一拍留给静止或一次单一切片；不要在片尾同时开新字、新图、新色块。
- `captions` 固定 `none`；画面文字就是正文，不再叠字幕。

## 禁止

- 一场多主角、多句并列、长句解释；快闪不铺陈因果。
- 两种相近字号同场；主字小于 0.2H；满屏只有一行居中文字而没有层次。
- 给文字描边、给卡片画蓝色 UI 边框、给图像填字叠阴影或棋盘填充。
- 用 `Math.random` / `Date.now` / 外部 IO；`tt det` 必须两次一致。
- 在同一场景写 `scene.params`；本 recipe 只收 `scene.code`。

## 参数速查

| 项 | 取值 |
|---|---|
| `RULES.safeMargin` | `0.025` |
| `RULES.scale` | `title 2 / label 0.72 / note 0.5`（起点） |
| 一拍 | `0.4644s`（半拍 `0.2322s`） |
| 单场上限 | `2.4s` |
| 底色 | `#0A0A0A` / `#FFFFFF` / `#FF4D00` / `#12305C` |
| 字体 | 主字 `sans-900`，微标签 `sans-400`（在 `resources` 声明） |
| 字幕 | `none` |
| 主体上限 | 实拍 ≤ `1/3` 场；图像填字 ≤ `1/4` 场且不连续 |

## 交付前

- `tt build`、`tt stills`、`tt qa`、`tt det`。
- `qa` 的 `must` 必须为 0：现在只抓 `RENDER_PAGE_ERROR` 与空墨迹；排版是否安全靠 12 格联系表自己看。装饰层请走 `api.canvas()` 离屏合成，不要在主画布重复 `fillText`。
- `captions` 固定 `none`；画面文字就是正文，不要再叠字幕。
- 不导出 MP4，除非用户明确要求。
